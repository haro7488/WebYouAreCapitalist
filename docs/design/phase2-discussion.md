## 1. AP 삭제 → 현금 = 행동력

- AP 시스템 완전 제거
- 모든 행동(매입/매각/업그레이드)은 현금만 있으면 무제한 수행
- 턴당 행동 제한 없음, **돈이 곧 행동력**

## 2. 조사 시스템 리워크

### 조사 수행 조건
- **정보 섹터** 기업 보유 시에만 조사 가능
- 보유량 = 턴당 조사 횟수

| 자산 | 티어 | 비용 | 소득 | 조사 횟수/턴 |
|------|------|------|------|-------------|
| 정보회사 | 단일 | TBD | 낮음 | 1회 |

- 정보 기업은 **1종류만** (티어 구분 없음)
- 1개 보유 = 1회/턴, 복수 보유로 횟수 누적
- 소득이 낮음 → 투자 효율 vs 정보력 트레이드오프

### 조사의 가치 (A+C 조합)

**A. 숨겨진 정보 공개**
- 섹터 트렌드 변화 1턴 전 예고
- 자산 실제 수익률 확인 (표시값 ±20% 변동)
- AI 경쟁사 다음 행동 힌트

**C. 리스크 감소**
- 이벤트 숨겨진 3번째 선택지 해금 (더 유리한 옵션)
- 매각 시 가격 보너스 (85% → 90~95%)
- 매입 선점권 (AI와 경합 시 우선권)

## 3. 현금 보유의 이유 = 이벤트

### 이벤트 비율

| 유형 | 비율 | 설명 |
|------|------|------|
| 💰 기회형 | 50% | 현금 쓰면 큰 이득 (비밀 매물, 로비, 적대적 인수) |
| ⚖️ 선택형 | 30% | 트레이드오프 (돈 안 들어도 됨) |
| 🔴 압박형 | 20% | 현금 없으면 자산 피해 (세금, 소송, 설비 고장) |

### 설계 원칙
- 벌칙보다 **보상으로 유도** (긍정적 동기)
- 기회를 놓친 아쉬움 > 강제 피해의 짜증
- 평균 2~3턴에 한 번 현금이 필요한 상황

### 기회형 이벤트 예시
- 비밀 매물: $400 → T2 자산 50% 할인 획득
- 로비 기회: $500 → 원하는 섹터 hot 전환
- 적대적 인수: $600 → AI 자산 1개 탈취
- 내부자 거래: $300 → 3턴간 소득 +50%

### 압박형 이벤트 예시
- 세금 징수: $200 납부 또는 자산 1개 압류
- 설비 고장: $150 수리 또는 소득 2턴 정지
- 소송: $300 합의 또는 영향력 -20 + 자산 가치 -30%

## 4. 결과적 플레이 패턴

```
매 턴 핵심 고민: 얼마를 투자하고 얼마를 남길까?

- 올인 전략 → 수익 최대, 이벤트 리스크 높음
- 비상금 전략 → 안정적, 기회도 활용 가능
- 현금 비축 전략 → 기회 이벤트 극대화 노림
```

## 5. 특성(Trait) 시스템

### 설계 원칙
- **획득/제거:** 이벤트 전용 — 매입이나 행동으로 직접 조작 불가
- **영구:** 런 끝까지 유지 — 이번 런의 유저 정체성
- **제거 불가 (직접):** 다른 이벤트에서 제거 선택지가 나와야만 가능
- **항상 선택권 보장:** 특성이 걸린 선택지엔 반드시 대안 존재 (강제 부여 없음)

### 특성 전용 이벤트
- 특정 특성 보유 시에만 열리는 선택지 존재
- 나쁜 특성도 전용 이벤트 보상이 있어서 **유지하는 전략적 가치**가 있음
  - 📰 악명 → "스캔들 이용" 해금 (큰 현금)
  - 💥 무모함 → "무모한 도전" 해금 (고위험 고수익)
  - 😰 의심병 → "과잉 조사" 해금 (조사 효과 2배)

### 특성 조합 = 플레이 스타일
- 🤝+👁️ → 정보 특화
- 💥+📰 → 고위험 고수익
- ⚙️+🔮 → 안정형

## 6. 구현 원칙: 데이터/로직 분리

### 원칙
- 게임 데이터는 **JSON 파일**로 관리
- 로직(계산, 판정, 상태 변경)은 **TS 파일**에서 JSON을 읽어 처리
- JSON에 함수 불가 → 이벤트 조건 등은 **선언형 태그**로 표현

### 디렉토리 구조

```
src/game/
  data/                    ← 순수 데이터 (JSON)
    assets.json            ← 자산 정의
    events.json            ← 이벤트 정의 (조건은 선언형 태그)
    traits.json            ← 특성 정의
    balance.json           ← 밸런스 상수 (시작금, 지출, 배율 등)
    glossary.json          ← 용어 사전
    names.json             ← 기업명
  schema/                  ← JSON → TS 타입 브릿지
    assets.schema.ts       ← import JSON + 타입 캐스팅/검증
    events.schema.ts
    traits.schema.ts
    balance.schema.ts
    glossary.schema.ts
    names.schema.ts
  logic/                   ← 순수 로직
    economy.ts             ← 소득/지출/시장풀 계산
    engine.ts              ← 게임 루프, 액션 처리
    events.ts              ← 이벤트 조건 판정, 발생 로직
    market.ts              ← 시장/섹터 상태 변경
    competitor/            ← AI 전략
  types.ts                 ← 타입 정의
  index.ts                 ← barrel export
```

### 데이터 파일 (JSON) 규칙
1. 함수 없음 — 순수 데이터만
2. JSON-serializable 구조
3. 이벤트 조건은 선언형 태그:
   ```json
   { "conditions": { "minTurn": 10, "marketNot": "recession", "minInfluence": 60 } }
   ```
4. 로직 쪽에서 조건 해석기(evaluator)로 처리

### 스키마 레이어 규칙
1. JSON import + TS 타입 캐스팅
2. 필요 시 런타임 검증 추가
3. 다른 모듈은 schema를 통해서만 데이터 접근

### 장점
- 코드 빌드 없이 밸런스 수정 가능
- DevPanel에서 런타임 로드/수정 가능
- 향후 서버에서 데이터 내려주기 가능 (밸런스 패치)
- 비개발자도 JSON 수정으로 기여 가능

## 7. 정부 시스템

### 정부 탭
- 기존: 현황 / 시장 / 포트폴리오
- 추가: **정부** — 인플레이션율, 정부 정책 히스토리, 예고(조사 시)

### 인플레이션
- 매 턴 모든 자산 가격 + 소득이 인플레이션율만큼 상승 (복리)
- 디플레이션 없음 (최소 0%)
- 수치는 매직넘버로 두고 밸런스 시 조정
- 이벤트로 인플레율 변동 가능

**효과:**
- 자산 가치 자연 성장 → 시장 풀 고갈 문제 완화
- 매입 비용도 상승 → 빨리 살수록 유리
- 현금 보유 = 인플레에 잠식 → 현금 비축의 숨은 페널티

### 정부 이벤트
- 매 턴 1개 고정, 일반 이벤트와 **별개**
- 플레이어 선택 불가 (정부가 결정)
- 조사하면 다음 턴 정부 이벤트 미리 확인 가능

**정부 이벤트 예시:**
- 금리 인상/인하 → 인플레 변동
- 섹터 규제 강화/완화 → 매입 비용 변동
- 보조금 지급 → 특정 섹터 소득 보너스
- 세금 인상/감면 → 전체 지출 변동

## 8. 승리 조건 + 목표 시스템

### 승리 조건
- **순자산 1위 = 승리** (30턴 종료 시 AI 대비)

### 목표 시스템
- 런 시작 시 3개 목표 중 1개 선택
- 달성 시 순자산에 보너스 직접 가산
- 목표 = 유형(template) + 스토리(flavor)
- 같은 유형으로 스토리만 다른 목표를 쉽게 추가 가능

### 목표 유형
- 지배형: 섹터 지배 조건
- 자산형: 순자산/현금 기준
- 수집형: 섹터 진출 수
- 영향력형: 영향력 수치
- 서바이벌형: 매 턴 조건 유지
- 특성형: 특성 보유 수

### 데이터 구조 (JSON)
```json
{
  "id": "tycoon-dream",
  "name": "재벌의 꿈",
  "description": "3개 산업을 지배하라",
  "type": "domination",
  "condition": { "dominatedSectors": { "min": 3 } },
  "bonus": 3000
}
```

## 9. AP 삭제 후 턴 구조

### 턴 흐름
```
Planning: 자유 행동 (현금이 허락하는 한 무제한)
  - 매입/매각/업그레이드: 현금 기반
  - 조사: 정보 기업 보유량만큼
  - 턴 종료 버튼
→ Government: 정부 이벤트 (선택 불가, 확인만)
→ Event: 일반 이벤트 1~2개 (순차 선택)
→ Resolution: 인플레 적용 + 소득 정산
→ Result: 결과 확인
```

### 행동 제한: 없음
- 현금 자체가 제한 역할
- 이벤트(50% 기회형)가 현금 보유 유인 → 자연스러운 페이싱
- 인플레가 현금 비축 페널티
- 조사가 턴 내 행동 순서를 만듦 (조사 먼저 → 판단 후 행동)
- 인위적 제한 불필요

## 10. 정보 섹터 상세

### 정보 기업
- **1종류만** (티어 구분 없음)
- 1개 보유 = 1회/턴 조사
- 복수 보유로 횟수 누적 (3개 = 3회/턴)
- 비용/소득은 밸런스 시 확정

### 조사
- 대상을 **플레이어가 선택**
- 결과는 **순수 정보 제공** (대상 행동에 개입 없음)
- 정보로 다음 턴 판단을 유리하게

### 조사 대상

| 대상 | 얻는 정보 |
|------|----------|
| 섹터 | 다음 턴 트렌드 변화 예고 |
| 정부 | 다음 턴 정부 이벤트 미리 확인 |
| 경쟁사 | AI 다음 행동 힌트 |
| 자산 | 특정 자산의 실제 수익률 확인 |
| 이벤트 | 다음 턴 일반 이벤트 미리 확인 |

## 12. 특성 효과 연동

### 원칙
- 특성 효과도 **JSON 선언형**
- 로직에서 플레이어 traits를 읽고 effects 합산하여 계산 반영

### 데이터 구조
```json
{
  "id": "efficient",
  "name": "효율 경영",
  "type": "positive",
  "icon": "⚙️",
  "description": "기본 지출 -30%",
  "effects": { "expenseMultiplier": 0.7 }
}
```

### 지원 효과 키

| 키 | 설명 |
|----|------|
| `expenseMultiplier` | 지출 배율 |
| `revenueMultiplier` | 소득 배율 |
| `purchaseDiscount` | 매입 할인율 |
| `sellBonus` | 매각 비율 보너스 |
| `investigationBonus` | 조사 횟수 추가 |
| `influenceGainMultiplier` | 영향력 획득 배율 |

## 13. 파산 처리

### 방식: 마이너스 허용 + 페널티
- 현금이 0 미만으로 떨어질 수 있음 (빚 상태)
- 빚 상태일 때 매 턴 이자 발생
- 이자율/세부 수치는 밸런스 시 확정
