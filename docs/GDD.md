# WebYouAreCapitalist - 게임 디자인 문서 (Phase 2)

> 턴제 경영 로그라이트 웹게임. 소액 투자자에서 시작해 30턴 안에 순자산 1위 자본가로 성장하라.

---

## 1. 게임 개요

| 항목 | 내용 |
|------|------|
| 장르 | 턴제 경영 로그라이트 |
| 플랫폼 | 웹 (모바일/PC 반응형) |
| 기술 스택 | React 19, TypeScript 5, Zustand 5, Tailwind CSS 3 |
| 1회 플레이 | 30턴 (약 10~15분) |
| 핵심 키워드 | 현금 경영, 인플레이션, 특성, 정부 대응, 정보전 |

### 게임 컨셉

플레이어는 $1,000를 가진 소액 투자자다. **현금이 곧 행동력** — AP 없이 돈이 허락하는 한 무제한으로 행동한다. 7개 섹터(외식/기술/부동산/물류/에너지/금융/**정보**)에서 자산을 매입하고, 포트폴리오 소득으로 성장한다. 매 턴 정부 정책이 인플레이션을 일으키고, 이벤트가 특성을 부여하며, AI 경쟁사 3곳과 순자산 1위를 다툰다. 30턴 후 **순자산 1위**가 승리.

**핵심 메시지: 현금을 쓰지 않으면 수입이 0이다.** 자산만이 유일한 수입원이며, 투자해야 번다.

### 로그라이트 요소

- **런 단위 플레이**: 매 런은 독립적. 30턴 후 승패 판정.
- **시드 기반 RNG**: 동일 시드 → 동일 이벤트/시장 (Mulberry32). 리플레이 가능.
- **메타 진행**: 런 점수의 일부가 메타 화폐로 전환. 영구 업그레이드 구매.
- **런 간 초기화**: 자금, 자산, 영향력, 특성은 매 런 리셋. 메타 업그레이드만 유지.

## 2. 핵심 시스템 요약

| 시스템 | 핵심 |
|--------|------|
| **경제** | 현금 = 행동력. AP 없음. 돈이 허락하는 한 무제한 행동 |
| **이벤트** | 매 턴 고정 1개 + 추가 확률. 기회형 50% / 선택형 30% / 압박형 20% |
| **특성** | 이벤트로만 부여/제거. 영구 지속. 항상 선택권 보장. JSON 선언형 |
| **정부** | 매 턴 정부 이벤트 1개. 인플레이션(가격+소득 복리). 정부 탭 |
| **조사** | 정보회사 보유 시 사용. 1개당 1회/턴. 대상(섹터/경쟁사) 선택 |
| **목표** | 3개 목표 중 1개 선택. 달성 시 순자산에 보너스 가산 |
| **파산** | 현금 마이너스 허용 + 이자 페널티. 매각 자산 없으면 게임오버 |

## 3. 턴 구조

```
  자유 행동        정부           이벤트          정산           결과
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│ 무제한    │→│ 정부 이벤트│→│ 일반 이벤트│→│ 경제 계산 │→│ 결과 표시 │→ 다음 턴
│ 매입/매각 │  │ 인플레이션│  │ 특성 부여 │  │ 소득/지출 │  │ 순위 변동 │
│ 업그레이드│  │ 정책 선택 │  │ 선택지    │  │ 가치 변동 │  │ 다음 턴   │
│ 조사      │  │ 매 턴 1개│  │ 고정+추가 │  │ 자동 처리 │  │          │
└──────────┘  └──────────┘  └──────────┘  └──────────┘  └──────────┘
 (현금 소진까지)  (필수)         (필수)        (자동)
```

### 3.1 자유 행동 (Free Action)

현금이 허락하는 한 무제한으로 행동한다. AP 개념 없음.

| 행동 | 비용 | 설명 |
|------|------|------|
| **매입** | 자산 가격 | 19개 자산 중 하나 구매 |
| **매각** | 무료 | 보유 자산을 팔아 현금화 |
| **업그레이드** | 자산별 비용 | 보유 자산 레벨 업 (소득 증가) |
| **조사** | 무료 (정보 자산 필요) | 정보 자산 1개당 1회/턴, 대상 선택 |
| **턴 종료** | - | 즉시 다음 페이즈로 |

### 3.2 정부 (Government)

매 턴 정부 이벤트 1개가 **고정 발생**한다. 인플레이션, 규제, 보조금 등.

- 인플레이션: 자산 가격과 소득이 매 턴 복리로 변동
- 정부 정책에 대한 선택지 제공 (수용/저항/로비 등)
- 정부 탭에서 현재 정책 상태, 인플레이션율, 예고 확인

### 3.3 이벤트 (Event)

매 턴 **고정 1개** + 변동성에 따라 **추가 발생** 가능.

| 유형 | 비율 | 특징 |
|------|------|------|
| 기회형 | 50% | 이득 기회 제공. 행동 시 보상 |
| 선택형 | 30% | 트레이드오프. 선택에 따라 결과 분기 |
| 압박형 | 20% | 손실 회피 상황. 비용 지불로 피해 감소 |

- **특성 부여/제거**: 이벤트 선택에 따라 영구 특성이 부여되거나 제거됨
- **항상 선택권**: 어떤 이벤트든 복수 선택지가 있고 하나를 필수 선택

### 3.4 정산 (Resolution)

시스템이 자동으로 처리:

1. 자산별 패시브 소득 계산 (시장/섹터/업그레이드/지배력/특성/인플레이션 배율 적용)
2. 이벤트 효과 적용
3. 기본 지출 차감
4. 자산 가치 업데이트 (appreciation + 인플레이션)
5. 글로벌 시장 상태 업데이트
6. 섹터 트렌드 업데이트
7. 영향력 자연 감소 (-1/턴)
8. **마이너스 잔고 이자** 적용 (파산 페널티)
9. 잔고 갱신, 순위 갱신

### 3.5 결과 (Result)

이번 턴의 소득/지출/순자산 변동/순위 변동을 보여주고, "다음 턴" 클릭.

## 4. 경제 시스템

### 기본 수치

| 항목 | 값 | 설명 |
|------|-----|------|
| 시작 자금 | $1,000 | 메타 업그레이드로 증가 가능 |
| 기본 수익 | $0/턴 | 자산 소득이 유일한 수입원 |
| 기본 지출 | $15/턴 | 생활비. 인플레이션 적용 |
| 시작 영향력 | 0 | 범위: 0~100 |
| AP | 없음 | 현금 = 행동력 |

### 순수익 공식

```
자산소득  = Σ(자산.baseIncome × 업그레이드배율 × 시장배율 × 섹터트렌드배율
            × 지배력배율 × 인플레이션배율 × 특성배율)
총수익    = floor(자산소득 × 이벤트수익배율 × 메타수익배율)
총지출    = floor(기본지출 × 인플레이션배율 × 이벤트지출배율)
순수익    = 총수익 - 총지출 + 이벤트직접금액
잔고      = 잔고 + 순수익
```

### 파산 규칙

| 조건 | 결과 |
|------|------|
| 현금 < 0 | **마이너스 허용** — 매 턴 이자 페널티 발생 |
| 현금 < 0 **이고** 매각 가능 자산 없음 | **파산** — 즉시 런 종료 |
| 턴 30 도달 | **완주** — 정상 런 종료 |

```
이자 페널티 = |마이너스 잔고| × 이자율/턴
```

마이너스 상태에서도 자산이 있으면 매각하여 회복 가능.

## 5. 자산 시스템

### 7섹터 19개 자산 (6섹터 × 3티어 + 정보 1개)

| 섹터 | Tier 1 (진입) | Tier 2 (성장) | Tier 3 (지배) |
|------|--------------|--------------|--------------|
| **외식** | 포장마차 $100 | 레스토랑 $400 | 프랜차이즈 $1,200 |
| **기술** | 앱 스타트업 $150 | SaaS 기업 $500 | 테크 대기업 $1,500 |
| **부동산** | 원룸 임대 $200 | 상가 건물 $600 | 오피스 타워 $2,000 |
| **물류** | 택배대행 $120 | 물류센터 $450 | 물류대기업 $1,300 |
| **에너지** | 주유소 $140 | 발전소지분 $500 | 에너지대기업 $1,600 |
| **금융** | P2P 대출 $180 | 투자 펀드 $550 | 은행 지분 $1,800 |

| 섹터 | 자산 | 비용 | 소득 | 비고 |
|------|------|------|------|------|
| **정보** | 정보회사 | TBD | TBD | 티어 구분 없음. 1개당 조사 1회/턴 |

> 정보 섹터는 티어 구분 없이 단일 자산(정보회사)만 존재. 보유 수만큼 조사 가능.

### 자산 수익 구조

```
턴 소득 = baseIncome × 업그레이드배율 × 시장배율 × 섹터트렌드배율
          × 지배력배율 × 인플레이션배율 × 특성배율
```

### 업그레이드

```
업그레이드 비용 = 자산원가 × 0.3 × (현재레벨 + 1)
소득 배율     = 1.25^레벨 (지수적 증가)
최대 레벨     = 3
```

### 매각

```
매각금액 = floor(현재가치 × 매각효율)
```

- 매각효율은 시장 상태에 따라 변동
- 업그레이드 비용은 매각 시 반환되지 않음

## 6. 조사 시스템

### 기본 규칙

- **정보회사 보유가 필수 조건**
- 정보회사 1개당 **1회/턴** 조사 가능 (N개 보유 = N회/턴)
- 자유 행동 페이즈에서 사용
- 조사 자체는 무료 (정보회사 보유가 비용)

### 조사 대상

| 대상 | 얻는 정보 | 전략적 가치 |
|------|----------|------------|
| 섹터 트렌드 | 다음 턴 해당 섹터 방향 | 매입/매각 타이밍 |
| 경쟁사 포트폴리오 | 특정 경쟁사의 보유 자산 | 지배권 경쟁 판단 |
| 경쟁사 전략 | 전략 타입 공개 | 다음 행동 예측 |
| 시장 전환 | 글로벌 시장 남은 턴 + 전환 방향 | 거시 전략 |

### 정보 섹터의 전략적 가치

- 정보회사는 소득이 낮지만 조사 능력이 핵심 자원
- 정보회사를 많이 보유할수록 턴당 조사 횟수 증가 → 정보 우위
- 다른 섹터 투자 타이밍을 최적화하는 "메타 섹터"

## 7. 이벤트 시스템

### 기본 규칙

- 매 턴 **고정 1개** + 변동성에 따라 추가 발생
- 모든 이벤트는 **복수 선택지** 제공, 하나 필수 선택
- 이벤트 선택에 따라 **특성 부여/제거**
- 최근 5턴 내 같은 이벤트 반복 없음

### 이벤트 유형 분포

| 유형 | 비율 | 설명 | 예시 |
|------|------|------|------|
| **기회형** | 50% | 이득 기회. 적극 행동 시 보상 | 무역 호황, 파트너십 제안 |
| **선택형** | 30% | 트레이드오프. 전략에 따라 최적 다름 | 기술 혁신, 소비 트렌드 변화 |
| **압박형** | 20% | 피해 최소화. 비용 지불로 손실 감소 | 금융 위기, 세무 조사 |

### 이벤트 효과 타입

| 효과 | 설명 | 지속 |
|------|------|------|
| `money` | 직접 자금 변화 | 즉시 |
| `influence` | 영향력 변화 | 즉시 |
| `trait` | 특성 부여/제거 | 영구 (제거 이벤트까지) |
| `incomeMultiplier` | 소득 배율 | 해당 턴 |
| `expenseMultiplier` | 지출 배율 | 해당 턴 |
| `sectorShift` | 섹터 트렌드 강제 전환 | 다음 전환까지 |
| `marketShift` | 글로벌 시장 강제 전환 | 다음 전환까지 |
| `freeAsset` | 무료 자산 획득 | 즉시 |

## 8. 특성 시스템

### 기본 규칙

- **이벤트로만** 부여/제거 (매입/업그레이드로는 획득 불가)
- **영구 지속** — 제거 이벤트가 발생할 때까지
- **항상 선택권** — 특성 부여/제거 여부를 플레이어가 선택 가능
- **JSON 선언형** — 효과를 데이터로 정의, 로직은 엔진이 해석

### 특성 구조 (JSON)

```json
{
  "id": "market-insider",
  "name": "시장 내부자",
  "description": "금융 자산 소득 +15%",
  "effects": [
    { "type": "incomeMultiplier", "sector": "finance", "value": 1.15 }
  ],
  "source": "partnership-offer",
  "removable_by": ["media-scandal"]
}
```

### 특성 효과 타입

| 효과 | 설명 |
|------|------|
| `incomeMultiplier` | 특정 섹터/전체 소득 배율 |
| `expenseMultiplier` | 지출 배율 |
| `purchaseDiscount` | 매입 할인율 |
| `sellBonus` | 매각 보너스율 |
| `influencePerTurn` | 턴당 영향력 추가 증감 |
| `eventProbability` | 이벤트 발생 확률 보정 |

### 전략적 의미

- 특성은 빌드를 정의: "금융 특화 빌드", "정보 독점 빌드" 등
- 좋은 특성 유지 + 나쁜 특성 회피가 이벤트 선택의 핵심 기준
- 로그라이트 런마다 다른 특성 조합 → 리플레이어빌리티

## 9. 정부 시스템

### 기본 규칙

- **매 턴 정부 이벤트 1개** 고정 발생 (일반 이벤트와 별도)
- 인플레이션은 복리로 누적
- 정부 탭에서 현재 상태 확인

### 인플레이션

```
인플레이션 누적 = (1 + 인플레이션율)^경과턴
자산 가격      = 기본가격 × 인플레이션 누적
소득           = 기본소득 × 인플레이션 누적
지출           = 기본지출 × 인플레이션 누적
```

- 가격과 소득이 함께 오르므로 ROI 비율은 유지
- **지출도 오르므로** 투자하지 않으면 실질적으로 손해가 커짐
- 인플레이션율은 정부 이벤트에 따라 변동

### 정부 이벤트 예시

| 이벤트 | 효과 | 선택지 |
|--------|------|--------|
| 금리 인상 | 인플레이션율 변동 | 대응/수용 |
| 산업 보조금 | 특정 섹터 지원 | 신청/포기 |
| 세금 인상 | 지출 증가 | 절세/수용/로비 |
| 규제 완화 | 특정 섹터 제한 해제 | 진입/관망 |

---

## 10. 시장 시스템

### 글로벌 시장 상태

| 상태 | 소득 배율 | 변동성 | 설명 |
|------|----------|--------|------|
| 호황 (boom) | ×1.3 | 낮음 | 전반적 수익 증가, 안정적 |
| 보합 (stable) | ×1.0 | 보통 | 기본 상태 |
| 불황 (recession) | ×0.7 | 높음 | 수익 감소, 이벤트 빈발 |

### 전환 확률 매트릭스

| 현재 → 다음 | 호황 | 보합 | 불황 |
|-------------|------|------|------|
| **호황** | 20% | 50% | 30% |
| **보합** | 30% | 40% | 30% |
| **불황** | 30% | 50% | 20% |

시장 상태는 4~8턴 유지 후 전환.

### 섹터 트렌드

| 트렌드 | 소득 배율 | 가치 변동 |
|--------|----------|----------|
| 뜨거움 (hot) | ×1.3 | +2%/턴 |
| 중립 (neutral) | ×1.0 | 기본 |
| 침체 (cold) | ×0.7 | -1%/턴 |

- 각 섹터 독립적으로 2~6턴 유지 후 전환
- 글로벌 시장이 섹터 트렌드 전환 확률에 영향

## 11. 지배력 시스템

같은 섹터에 자산을 집중하면 지배력 보너스를 얻는다.

| 같은 섹터 자산 수 | 등급 | 소득 보너스 | 특수 효과 |
|-----------------|------|-----------|----------|
| 1개 | 진입자 | 없음 | 없음 |
| 2개 | 경쟁자 | +10% | 없음 |
| 3개 | 지배자 | +25% | 해당 섹터 이벤트 제3 선택지 해금 |

## 12. AI 경쟁사

### 동일 엔티티 원칙

플레이어와 경쟁사는 같은 `Company` 엔티티. 게임 엔진은 human/ai를 구분하지 않는다.

| 항목 | 값 |
|------|-----|
| 경쟁사 수 | 3 |
| 시작 자금 | 플레이어와 동일 |
| 이름 | 시드 RNG로 한국형 기업명 배정 |

### 전략 타입

| 타입 | 행동 패턴 | 리스크 |
|------|----------|--------|
| 보수형 | Tier 1~2 분산, 현금 비축 | 낮음 |
| 공격형 | Tier 2~3 집중, 호황 시 공격 매입 | 높음 |
| 지배형 | 한 섹터 올인, 지배력 극대화 | 중간 |
| 기회형 | hot 섹터 추격매수, 시세차익 | 높음 |

## 13. 승리 조건

### 기본 승리: 순자산 1위

```
순자산 = 현금 + Σ(보유 자산 현재가치)
```

30턴 종료 시 **순자산 1위**가 승리.

### 목표 시스템 (보너스)

런 시작 시 **3개 목표 중 1개**를 선택한다. 달성 시 순자산에 보너스를 가산.

| 목표 예시 | 조건 | 보너스 |
|----------|------|--------|
| 섹터 지배자 | 2개 이상 섹터 지배 | 순자산 +20% |
| 자본 제왕 | 순자산 $30,000 이상 | 순자산 +15% |
| 정보왕 | 정보 섹터 지배 달성 | 순자산 +25% |

목표 미달성 시 보너스 없음 (페널티 없음).

## 14. 영향력 시스템

| 구간 | 타이틀 | 매입 할인 | 이벤트 보너스 |
|------|--------|----------|-------------|
| 0~19 | 무명 투자자 | 0% | 0% |
| 20~39 | 주목받는 투자자 | 0% | 5% |
| 40~59 | 영향력 있는 투자자 | 5% | 10% |
| 60~79 | 시장의 큰 손 | 10% | 15% |
| 80~100 | 자본가 | 15% | 20% |

- 자연 감소: -1/턴
- 매입 시 증가: Tier 1 +2, Tier 2 +3, Tier 3 +5
- 이벤트 선택에 따라 증감

## 15. 데이터/로직 분리 아키텍처

### 원칙

| 레이어 | 역할 | 형식 |
|--------|------|------|
| **데이터** | 자산, 이벤트, 특성, 정부 이벤트 정의 | JSON |
| **스키마** | 데이터 유효성 검증 | TypeScript (Zod 등) |
| **로직** | 효과 해석, 턴 처리, 경제 계산 | TypeScript |

### 데이터 예시 (자산)

```json
{
  "id": "food-cart",
  "name": "포장마차",
  "sector": "food",
  "tier": 1,
  "cost": 100,
  "baseIncome": 8,
  "appreciation": 0.01,
  "risk": "low",
  "marketMultiplier": { "boom": 1.3, "stable": 1.0, "recession": 0.8 }
}
```

### 데이터 예시 (이벤트)

```json
{
  "id": "trade-boom",
  "name": "무역 호황",
  "type": "opportunity",
  "minTurn": 6,
  "weight": 7,
  "condition": { "market": { "not": "boom" } },
  "choices": [
    {
      "label": "해외 투자",
      "effects": [
        { "type": "incomeMultiplier", "value": 1.4 },
        { "type": "marketShift", "value": "boom" },
        { "type": "influence", "value": 5 }
      ]
    },
    {
      "label": "국내 집중",
      "effects": [
        { "type": "incomeMultiplier", "value": 1.2 },
        { "type": "influence", "value": 2 }
      ]
    }
  ]
}
```

### 장점

- 이벤트/자산/특성 추가 시 JSON만 편집 (코드 변경 불필요)
- 밸런스 조정이 데이터 레이어에서 완결
- 모딩/확장 용이

| 탭 | 내용 |

```

## 17. 메타 진행 시스템

### 메타 업그레이드

| 이름 | 효과 (레벨당) | 최대 레벨 |
|------|-------------|----------|

| 투자 안목 | +8% 소득 배율 | 5 |

```
실제 비용 = 기본비용 × (현재레벨 + 1)
