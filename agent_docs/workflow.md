# 작업 워크플로우

## 작업 분할 원칙

1. 작업 시작 전 독립적 하위 작업으로 분할한다
2. 하위 작업은 File Ownership 경계(CLAUDE.md 참조)에 따라 나눈다
3. 각 하위 작업은 명확한 결과물(파일/기능)을 가져야 한다
4. 의존 관계가 있으면 순서를 명시한다

## 에이전트 팀 사용 기준

- 독립적인 하위 작업이 2개 이상이면 에이전트 팀 활용
- 동일 파일을 수정하는 작업은 같은 팀원에게 배정
- 순차 의존성이 강한 작업은 팀 대신 단일 세션 사용
- 단순 작업(1파일 수정, 버그 1건)은 서브에이전트 또는 단일 세션

## 팀 구성 가이드

| 작업 유형 | 팀원 구성 예시 |
|-----------|---------------|
| 새 기능 구현 | 게임 로직 + 스토어 + UI (최대 3팀원) |
| 버그 수정 | 조사 + 수정 (단일 세션 또는 2팀원) |
| 리팩토링 | 영역별 분할 (2-3팀원) |
| 코드 리뷰 | 보안 + 성능 + 테스트 (3팀원) |

## 팀원 작업 규칙

- 작업 완료 후 `npm run build`로 타입 체크 필수
- `src/game/types.ts` 수정 필요 시 리더에게 먼저 보고
- 각 팀원은 자기 영역 파일만 수정
- 팀원당 5-6개 작업 유지 (너무 적으면 유휴, 너무 많으면 혼란)

## 작업 흐름

```
요청 접수 → 작업 분할 → 팀 필요? → Yes → 팀 생성 → 작업 할당 → 병렬 실행 → 통합 검증
                                  → No  → 단일 세션에서 순차 처리
```
